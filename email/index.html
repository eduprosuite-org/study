RFC 6068 Mailto URI Technical Standard

The mailto URI scheme represents an internet standard governed by the Internet Engineering Task Force (IETF RFC 6068). It allows hyperlinks to specify destination email mailboxes, carbon copy recipients, subject lines, and multi-line body parameters.

📧 Mailto Protocol URI Syntax

mailto:<email>?subject=<encoded_subject>&body=<encoded_body>

1. Mailto Header Field Parameters Comparison

Supported header parameters in standard mobile barcode decoders:

Header Parameter URI Key Encoding Requirement Client Support
To (Recipient) Path segment (e.g. mailto:user@site.com) Standard ASCII email format 100% Universal across all OS
Subject Line ?subject=... Percent-encoded (e.g. %20 for spaces) Universal (iOS, Android, Windows)
Body Template &body=... Percent-encoded (e.g. %0A for newlines) Universal (iOS, Android, Windows)
Carbon Copy (CC) &cc=... Comma-separated email addresses Desktop clients & Advanced mobile apps

Frequently Asked Questions

How does an Email QR code work?
An Email QR code encodes an RFC 6068 mailto URI scheme (mailto:user@example.com?subject=Subject&body=Body). When scanned by a mobile device, it launches the default email client (Apple Mail, Gmail, Outlook) with the recipient, subject line, and body message already pre-filled.
Can I pre-fill both the subject line and the message body?
Yes. Our generator allows you to specify the recipient email address, subject line, and initial message body template, which are all URL-encoded into the mailto string.
Does the user still have to tap send?
Yes. For security and anti-spam reasons, mobile operating systems open the email composer for review. The user reviews the pre-filled message and taps the send button in their email client.
Are email addresses tracked or stored on your servers?
No. The entire QR generation process executes in client-side JavaScript inside your browser. No email addresses or message contents are ever logged or sent to any remote database.
